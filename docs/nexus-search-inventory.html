1. 整体架构

nexus 搜索是三层结构。最上面的 CLI/HTTP 是 human-facing 边界；中间 axum 是 auth+federation+delegation 的裁判层；最底下的 plugin 是纯 BM25+ANN 算法。

2. 4 种搜索算子

2.1 glob — 文件路径通配符 no index

找符合 *.rs / **/*.md 模式的路径。走文件系统 walk，不需要建索引。

用法

nexus glob 'src/**/*.py'
curl "http://localhost:8080/v2/search/glob?pattern=src/**/*.py&max_results=100"

参数

参数说明
pattern必填。globset 语法（*.rs、**/*.md）
root_pathwalk 起点，默认 /
max_results上限，默认 10000
sort_recency按 mtime 降序（最新在前）
zone_idadmin 才能指定别的 zone

2.2 grep — 内容正则搜索 no index

找匹配 regex 的行。walk + 逐行 match，不需要建索引。

用法

nexus grep 'fn main' --file-pattern '*.rs' --before-context 2 --after-context 2
curl "http://localhost:8080/v2/search/grep?pattern=fn+main&file_pattern=*.rs&ignore_case=true"

参数

参数说明
patternRust regex crate 语法
file_pattern限定文件名 glob（空 = 所有文件）
ignore_case忽略大小写
invert_match返回 不匹配的行
before_context / after_context上下文行数
sort_recency按文件 mtime 排序

2.3 query — 索引搜索 (BM25 / semantic / hybrid) needs index

全文 / 语义 / 融合搜索。使用前必须先建索引（见 2.4）。

用法

# CLI
nexus search query "how does auth work" --limit 20 --mode hybrid

# HTTP
curl -X POST http://localhost:8080/v2/search/query \
  -H 'Authorization: Bearer sk-xxx' \
  -H 'Content-Type: application/json' \
  -d '{"q":"how does auth work","query_type":"hybrid","limit":20}'

三种模式（query_type）

模式算法需要 embedder特点
keywordBM25 (tantivy)❌最快 · 精确词匹配
semanticANN cosine (hnsw)✅语义相近 · 无需精确词
hybrid 推荐两者融合 (RRF)✅最准 · 默认权重 0.5

高级 knobs (POST body 里)

字段作用
alphahybrid 里 semantic vs keyword 权重 (0-1, 默认 0.5)
fusion_methodrrf / weighted / rrf_weighted
path_filter只搜路径前缀下的文档
recency_modeoff / on / auto（新文件加权）
path_prefix_boosts{"/docs/": 1.5} 按目录分层加权
expandmacro — 每个 hit 返回上下 chunk 拼接
chunks_per_page同一文件里 chunk 数上限（防单文件霸榜）

2.4 index / refresh — 建/更新索引 必做

没建索引，query 永远返回空。

用法

# 递归建全量
nexus search index /docs

# 只顶层
nexus search index /docs --no-recursive

# 看进度
nexus search stats

关系

算子做什么什么时候用
Index全量扫 + 全量写入第一次 / 大改动后
Refresh增量（只处理 mtime 变了的）日常刷新 · 定期 cron
NotifyFileChange单文件通知on-write hook
IndexDocuments带内容的批量写入（跳过 walk）caller 手上已有文本
写-可搜契约（#4736）：CLI 会同步等 last_index_seq 追上索引才返回；返回后 query 立即能查到刚建的内容。

3. 三种调用路径

同样的 glob/grep/query，你有 3 条路径可以用。选哪条看你在哪一层。

路径场景延迟示例
In-process syscall
最快		 跟 kernel 同 dylib / binary，如 sudocode 内嵌 ⚡ 微秒级（无序列化） KernelSyscall::sys_readdir(recursive=true, opts)
gRPC → plugin 跨进程但同机器 ~ms（loopback + proto） SearchService.Glob / Grep / Query
HTTP /v2/search/* 跨机器 · 走 auth 边界 · 走 federated dispatcher ~ms + 网络 GET /v2/search/glob
Syscall 关键事实：KernelSyscall trait 里 11 个 sys_*，没有独立的 sys_glob 或 sys_grep。glob = sys_readdir(recursive=true) + globset 过滤；grep = sys_readdir + sys_read + regex。plugin/HTTP/gRPC 只是把这些操作打包成一个 RPC。

换句话说，你在 in-process 时可以完全绕开 plugin，直接自己 walk + match — 这就是 sudocode glob/grep 工具的实现方式。

4. Federated (跨 zone) 搜索 — 自动

不需要配置任何东西。/v2/search/query 自动检测：

  • ≤1 zone：走原来的单 zone 快路径，无额外开销
  • >1 zone：并发 fan-out（Semaphore(8) + 每 leg timeout=5s），RRF 融合返回
  • 想强制单 zone：请求 body 里传 "zone_id": "eng" 就绕开

5. Cross-daemon (跨 daemon) 搜索 — 一个 env var 打开

如果你部署了多个 nexus daemon，各自拥有独立 zone，一个环境变量就打开跨机器搜索：

export NEXUS_SEARCH_REMOTE_ZONE_TARGETS="eng=http://peer-eng:2126,legal=https://peer-legal:2126"
nexusd-cluster serve

行为

  • Zone eng 的 leg → dial http://peer-eng:2126
  • Zone legal 的 leg → dial https://peer-legal:2126
  • SearchDelegation 走 tonic metadata（x-nexus-search-delegation-bin）
  • 对方 daemon 的 delegation_gate 自动 validate（zone allowlist · method allowlist · TTL）

Fail-loud

Typo 直接 boot 失败，不会静默：
• 缺 =（zone1:url1）→ MissingSeparator
• 空 zone_id / 空 URL / 重复 zone_id → 每种都有专门的 Err
Matches standing "fail loud on partial config" rule。

6. Plugin peer fanout — 别跟 cross-daemon 混淆

这是另一个东西，跟上面 cross-daemon 完全不同。
Plugin peer_fanoutDaemon cross-daemon
层Plugin 内部Daemon 之间
触发每次 query 无条件 fan-out（zone 在白名单内）zone 在 registry 里指向 remote target 才 fan-out
用途内容分片（一半索引在 A，一半在 B）zone-owner 分布（zone A 的数据只有 daemon-A 有）
Delegation❌✅ SearchDelegation on metadata
EnvNEXUS_SEARCH_PEER_PLUGINS + NEXUS_SEARCH_PEER_FANOUT_ZONESNEXUS_SEARCH_REMOTE_ZONE_TARGETS

Plugin peer_fanout 打开方式

export NEXUS_SEARCH_PEER_PLUGINS="host1:2126,host2:2126"
export NEXUS_SEARCH_PEER_FANOUT_ZONES="root,eng"      # 白名单
export NEXUS_SEARCH_PEER_TLS=true                     # 可选 TLS
export NEXUS_SEARCH_ALLOW_INSECURE_PEER=true          # 可选：允许 plaintext off-loopback（不推荐）
Shared cache（DRY）：Plugin peer_fanout 和 Daemon cross-daemon 共用同一个 PeerChannelCache（nexus_search_common::transport）—— 一处调整 TLS / 超时规则，两处生效。

7. 按场景选路径 / 3 步上手

决策表

我想…用这个需要建索引？
找路径 .py / .mdnexus glob❌
找 TODO 出现在哪些行nexus grep 'TODO'❌
找 "auth 怎么工作的"nexus search query "..." --mode hybrid✅
新加的文档想被搜到nexus search index /docs（refresh 更快）—
跨多个 zone有 ReBAC 权限就自动，否则先 grant—
跨多个 daemon 部署设 NEXUS_SEARCH_REMOTE_ZONE_TARGETS—
让新文件在结果里靠前POST body "recency_mode": "on"—
调 hybrid 权重POST body "alpha": 0.7（越大越偏 semantic）—
让某些目录得分翻倍POST body "path_prefix_boosts": {"/docs/": 1.5}—
返回上下文而不只是命中 chunkPOST body "expand": "macro"—

最快上手 3 步

# 1. 启动 daemon（如果没跑）
nexusd-cluster serve

# 2. 建一次索引（首次 / 大改动后）
nexus search index /path/to/your/docs

# 3. 搜
nexus search query "your question" --mode hybrid --limit 10

8. 环境变量一览

Env层作用
NEXUS_SEARCH_REMOTE_ZONE_TARGETSDaemonCross-daemon 总开关。zone1=url1,zone2=url2。空 → 单 daemon（默认）
NEXUS_SEARCH_PEER_PLUGINSPluginPlugin peer_fanout 的对端 host:port 列表
NEXUS_SEARCH_PEER_FANOUT_ZONESPluginPlugin peer_fanout 白名单 zone
NEXUS_SEARCH_PEER_TLSPluginPlugin peer_fanout 打开 TLS
NEXUS_SEARCH_ALLOW_INSECURE_PEERPlugin允许 plaintext off-loopback（越狱开关）
NEXUS_SEARCH_TITLE_ARMPlugin关闭 hybrid 里 title arm（默认开）
NEXUS_SEARCH_QUERY_EXPANSIONPlugin打开 LLM query expansion
NEXUS_SEARCH_PLUGIN_TARGETDaemon本地 plugin 的 gRPC 地址（一般不用改）

回顾

4 算子（glob / grep / query / index）× 3 路径（syscall / gRPC / HTTP）× 自动 federated（>1 zone）× 1 个 env var 打开 cross-daemon。任何 caller 只要能 curl 或 nexus <cmd>，全部功能都触达。
